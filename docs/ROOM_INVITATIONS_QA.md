# 房间二维码邀请与参赛房主模式验证

2026-09-15，本地 Java 服务与发布用 Web 产物，Android API 34 模拟器及 Harmony Pura X Max 模拟器。未更新公网服务。原生默认服务仍为 `http://8.133.216.39:8080`，测试设备单独使用本机自定义地址。

## 实现与边界

- Android、Harmony、Web 等待房间均支持房主生成邀请二维码；相机或浏览器识别后打开 Web，带入房间、邀请和 API 地址，填写昵称后加入。
- 房主仍然参赛。玩家/管理员模式只调整界面和可见操作；身份、人数、准备、游戏步骤、已提交的票及账本状态保持不变。
- 所有房间成员显示房主当前模式，并对新切换显示临时提醒。最近 20 条切换持久化；首次进入显示当前状态，已有房间短暂断线后补充新记录。断线期间不能即时通知。
- 管理员界面收起房主秘密身份、夜间知识和作画答案；投票、组队、任务及作画回到玩家模式。成员私有数据仍由 Java 按令牌返回。
- 邀请不能替代成员令牌或后台管理凭据；待加入邀请不会覆盖已有会话。满员、开局、失效房间、错误邀请、过期操作有服务端检查。扫码成员没有房间密钥时不显示空密钥入口。
- `PUBLIC_WEB_URL` 指定已部署网页入口，该网页来源代理 `/api/`；从默认 HTTP 手机端生成的 HTTPS 网页邀请使用 HTTPS 代理地址。详见 [部署与玩法说明](WEB_AND_SIX_CLOUD_GAMES.md)。

## 实际界面检查

1. Android 创建记账房间，显示二维码。对实际页面截图进行独立二维码解码，再在浏览器打开得到的链接，昵称加入成功；房主玩家/管理员界面分别显示个人操作与银行批量操作，开始、结束、下一局均可达。网页成员可见模式变化，刷新后恢复原成员。
2. Harmony 创建三人狼人房间并显示二维码，截图解码成功。已有另一房间的浏览器打开该邀请时提示先返回原房间，不覆盖身份；原房间解散后可继续邀请，待加入时刷新仍恢复邀请。
3. Android、Harmony、Web 同房，完成查牌确认、讨论、房主开始秘密投票、房主回到玩家模式投票及三端一致结算。本次随机发到三张村民，中央为强盗、预言家、狼人，无玩家夜间动作，直接进入讨论，三人各一票无人出局，村民胜；其他夜间身份由完整规则与真实客户端流程验证覆盖。
4. 实际捕获网页成员的「房主已切回玩家模式」「房主正在使用管理员模式」临时提醒及常驻状态。Harmony 也显示切换提醒与原生临时提示。切换不增加/移除参赛成员。
5. 原房主离开后，Web 成员接任房主，继续下一局并生成二维码；对 Web 二维码截图独立解码，链接与相同房间邀请一致。
6. 在最终安装包中，Harmony 以普通成员重新加入，Web 房主开始第二局。Android 与 Harmony 均先展开个人身份卡；Web 切换管理员模式后，两端收到公开模式更新并保留已展开的身份卡，分别通过 `android-mode-ui.log`、`harmony-mode-ui.log` 与前后截图核实。Web 邀请链接复制与关闭弹窗也已验证。
