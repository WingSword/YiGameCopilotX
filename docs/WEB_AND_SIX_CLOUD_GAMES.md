# 六种网络游戏与 Web 部署

Java 工程仍在 Android 仓库的 `server/`。Android、Harmony、Web 共用房间协议，云端保管秘密身份、答案、阶段、计时和结果。上线时先替换 Java JAR，再更新客户端；本次开发只连接本机测试服务，没有部署到现有公网服务器。

## 默认地址和玩家身份

Android 与 Harmony 的内置默认服务保持 `http://8.133.216.39:8080`。测试地址只保存在测试设备的自定义服务设置中，不会进入发布包的默认值。已有房间会话继续连接加入时的服务；切换服务器前先退出当前房间。

Web 复用 KMP 共享界面、模型和客户端；HTTP 网页沿用默认地址，HTTPS 网页使用当前网站来源的 `/api/v1/rooms`。部署 `server/deploy/nginx.conf`，将 Web 文件放到 `/opt/yigame/web`，让同一 HTTPS 域名转发到 Java 服务。不要把 HTTPS 网页直接配置到 HTTP IP，否则浏览器会拦截混合内容。跨域部署可用 `WEB_ORIGINS` 允许准确的网页来源，不能以此绕过 HTTPS 限制。Nginx 的上游可在部署时改为已有服务器；原生客户端默认值不随之改变。

浏览器不提供稳定可靠的硬件唯一标识。本项目以服务器生成的随机成员 ID 和私密令牌区分玩家，Web 通过本地存储保留令牌。刷新、关闭重开、服务重启后可从「联机 → 返回已加入的房间」继续使用原身份；同一来源、同一浏览器配置中的标签页是同一玩家。更换浏览器、清理网站数据或结束无痕会话后不保证恢复。浏览器禁止本地存储时会提示先允许保存数据，避免默默丢失身份。房间号、昵称或设备自报 ID 均不能替代成员令牌。

依据：[MDN 本地存储](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)、[MDN 混合内容](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Mixed_content)。

## 手机与网页二维码邀请

房主在等待阶段进入「管理员模式 → 邀请玩家 · 二维码」。Android、Harmony 和 Web 都可以显示二维码；相机或浏览器识别后打开网页版，自动带入房间和邀请，填写昵称后加入。网页也可复制邀请链接，鸿蒙可长按链接复制。已有其他房间会话时先返回原房间离开，邀请不会覆盖玩家身份；未加入前刷新仍保留邀请。

在 Java 服务的环境中设置 `PUBLIC_WEB_URL=https://你的网页域名/`（可包含网页所在的子路径），并让该域名的 `/api/` 代理到同一 Java 服务。服务端优先使用这个地址，二维码里的 API 地址使用该网页来源，因此原生默认 HTTP 服务与 HTTPS 网页可以共存。配置后手机无须填写网页网址。未配置时 Web 使用当前页面，手机可填写已部署的网页地址；手动配置仍要求网页和服务协议兼容。不能将 localhost 用作供其他手机访问的发布地址。

二维码采用服务内置的 [Nayuki QR Code generator v1.8.0](https://github.com/nayuki/QR-Code-generator/tree/v1.8.0/java)，MIT 许可证随 JAR/源码包分发，不向第三方二维码服务传递邀请。链接片段仅含房间号、独立随机入房邀请及 API 地址，不含玩家令牌、房间密钥或后台管理凭据。片段在网页保存待加入邀请后移除；参见 [MDN URL fragment](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Fragment)。邀请受人数上限、等待阶段和房间有效期约束；房间解散或过期后不可使用。

## 房主玩家界面与管理员界面

房主始终占一个玩家名额并领取自己的身份。两种模式只切换界面：玩家模式完成自己的查牌、夜间行动、投票、组队、任务、作画和个人记账；管理员模式提供开始、讨论后发起投票、推进绘画回合、银行批量记账、再来一局和房间管理。管理员界面收起房主自己的秘密信息，不提供其他人的私密身份、任务票或答案。

切换经服务端确认后，所有正在房间内的成员都会收到临时提醒；顶部持续显示「房主正在使用管理员模式」或「房主正在使用玩家模式」。开局自动转为玩家模式，再来一局回到管理员模式。切换不会改变人数、准备状态、身份和已提交操作。最近 20 条切换记录随房间持久化，短暂断线恢复后补充提醒；首次进入显示当前模式，不重放之前所有提醒。离线期间无法即时接收，重新连接后更新。

### 阿瓦隆基础规则

查阅[发行方原版规则书公开副本](https://www.scribd.com/doc/288728587/The-Resistance-Avalon-Rules-en)。5–6 人配 2 名邪恶，7–9 人配 3 名，10 人配 4 名。默认使用梅林、派西维尔、刺客、莫甘娜；7 人起加入莫德雷德，10 人加入奥伯伦，其余为忠臣。服务端也接受人数、善恶比例正确的八种基础角色牌组，不含湖中仙女、兰斯洛特等扩展。

队长随机确定第一位，之后按座位顺序轮换。组队需超过半数同意，平票否决，连续五次否决则邪恶胜。所有表决结束才公布每人的组队票。善良只能提交任务成功，邪恶可选成功或失败；任务只公布失败牌总数，永不公开单人的任务牌。7 人及以上仅第四次任务需要两张失败牌，第五次仍只需一张。三次任务失败邪恶胜；三次成功后先进行刺杀，刺客命中梅林则邪恶胜，未命中则善良胜，之后才公开全部身份。

梅林看到除莫德雷德外的邪恶，包括奥伯伦；派西维尔看到梅林与莫甘娜的无区分候选；其他邪恶互认但不包含奥伯伦，奥伯伦不与邪恶互认。网络模式严格按上述基础规则执行，不借用本机玩法的可选第五轮变体。

接口沿用 `/game`：`roundId, stepId, choice`；组队 `choice=team` 另传 `targets`，之后为 `approve/reject`、`success/fail`、`player:<id>`。`game.avalon` 返回队长、任务轮次、队伍、连续否决数、任务历史和已提交人数。相同步骤重复相同操作不会二次执行，改票或旧阶段操作被拒绝。

### 你画我猜

参考[skribbl 官方玩法说明](https://skribbl.io/)的轮流作画和其他玩家猜词流程；以下是本项目明确采用的计分与时长，并非声称复刻该网站：每人画一次，每轮 90 秒，猜中者 +10，画者为每位猜中者 +5，最终最高分并列获胜。禁止靠文字或数字直接写答案是玩家共同遵守的游戏约定。

`room.drawing` 返回本轮画者、阶段、剩余时间、笔画和积分；答案仅画者可见，本轮结束后才公开。全部猜中或服务器计时到期会结束本轮；房主也可确认提前结束，处理画者暂时无法继续的情况。下一轮由房主推进。主动离开会中止整局，短暂断网保留成员与分数。

绘画接口 `/draw` 携带 `roundId, stepId, requestId, operation`；操作为 `start/stroke/undo/clear/guess/end/next`，`tick` 仅允许已过截止时间的回合。画板固定 4:3，坐标为 0–1000 的整数，每笔最多 96 点、每轮最多 120 笔；笔画在抬笔后同步。笔画、撤销、清空附带当前 `revision`，颜色为七种允许值，宽度 2–30。猜词提交 `guess`，其他玩家看不到未猜中的答案文本。每人每轮最多 100 次猜词，间隔至少 600 毫秒。

客户端先保存完整绘画指令再发送，响应丢失后可重试；服务器指纹避免重复落笔或加分。阶段和版本检查阻止旧画面覆盖新画面。没有实时语音或聊天服务，玩家可当面或使用自己的通话工具。

## Web 构建

使用项目 Gradle Wrapper 执行 `:composeApp:wasmJsBrowserDistribution`，发布目录为 `composeApp/build/dist/wasmJs/productionExecutable`。保留目录结构和字体许可证。需要支持当前 Kotlin/Wasm 所需 WebAssembly 功能的现代浏览器，Web 的局域网入口已隐藏。

若 Gradle 无法下载 GitHub 的工具，可自行从 [Binaryen 官方发布](https://github.com/WebAssembly/binaryen/releases/tag/version_125)取得并核对 125 版，在构建时传 `-Pyigame.binaryenExecutable=<wasm-opt 的绝对路径>`。该设置仅指定本地构建工具，不改变服务器地址、网络规则或发布配置。部署应启用压缩，并将 `.wasm` 以 `application/wasm` 返回。

Web 中文字体随包提供，不依赖外部字体网站；时间使用实际 UTC 时间戳，保证账本时间和记录排序。安卓及 Web 共用的绘画界面限制最大宽度；鸿蒙观察画板时不拦截页面滚动，绘画时才处理画笔手势。

## 后续鸿蒙共享适配

本次鸿蒙功能以现有 ArkUI 实现，Android/Web 复用 Compose。共享协议和展示模型放在 `shared/commonMain`，游戏裁决留在 Java 服务；后续迁移鸿蒙 Compose 时可复用客户端和界面，不应将云端秘密状态搬到客户端。跨端检查新增 Web 路径与字体二进制哈希，继续用正式客户端协议测试和原生界面联调保证行为一致。
