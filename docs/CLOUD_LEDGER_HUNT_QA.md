# 云端记账与猎巫镇扩展验收（2026-09-14）

## 规则核对与范围

已查阅 [Facade Games 发行方介绍](https://www.facadegames.com/products/salem-1692)及[发行方编写的第二版规则书](https://gamers-hq.de/media/pdf/fc/7d/89/FINAL_Salem_Rulebook_-2nd_Edition.pdf)。原版 Salem 1692 包含多张审判牌、手牌回合、指控和阴谋传染，警长不能守护自己。当前项目的猎巫镇是单身份简化玩法，两者并非同一套规则。

本轮将项目既有简化玩法接入网络房间，创建入口和私有提示均明确标注，不将其称为完整原版。4–12 人，至少一名女巫、一名警长和一名村民；云端负责洗牌、身份隔离、夜间行动、秘密投票、出局和胜负。警长可自守；目标或放逐最高票并列则无人出局；弃权不计票。女巫全部出局则村民胜，非女巫全部出局则女巫胜。已出局房主仍可推进讨论，离开成员会中止本局。

记账的四个场景是可调整的虚拟数额模板，不冒充特定桌游的强制规则：电子银行 1500000、地产资金 1500、积分赛 0、筹码 1000，可自行设置起始金额。

## 实现与交互

- Java 工程在 Android 仓库 `server/`，新增 `LedgerGame.java`、`HuntGame.java`；独立 Java 17 JAR，无数据库依赖。原有卧底、狼人及持久化快照继续兼容。
- Android 网络模型在 `shared/commonMain/online`，页面和网络适配器在 `composeApp`；Harmony 位于相邻 `YiGameCopilotX-Harmony`，保持原生 ArkUI 实现并使用同一服务协议。为后续 Compose 适配保留共享模型边界，本轮未迁移鸿蒙渲染框架。
- 云记账支持 2–20 人、玩家账户与公共池、本人支付、房主代记、需付款人确认的收款、批量发放、收至公共池、按座位顺序分配余数的均分、整批撤销、历史和 CSV。房主也不能代确认其他玩家的收款请求。
- 两端发请求前持久化完整指令，结果不确定时阻止新交易并提供原请求重试。服务端请求指纹防重复记账，版本校验阻止并发旧余额操作，落盘失败回滚。所有批量操作先验证全部账户再一次入账。
- 本机记账增加场景与起始金额、快捷数额、收付交换、全员收付及预览、整批撤销、CSV 和云端入口；编辑余额生成调账记录。旧账本兼容读取，历史按完整批次保留，筹码不允许负数。
- 修复鸿蒙批量交易使用同一毫秒时间戳作为列表标识、导致部分记录未显示的问题；撤销改为可见文字按钮。两端新交易默认选择有效玩家，避免初始收付都是银行。

日志与模拟器证据在 `artifacts/cloud-expansion/`。Java 测试中的 `AccessDeniedException` 是故意制造落盘失败的回滚用例，最终退出码为 0。

两端模拟器实际点通本机记账的场景重置、起始 0、批量预览/入账/撤销、快捷数额、收付交换、CSV、圆桌和云端入口。安卓 API 34 与 Harmony 模拟器接入同一个本机 Java 服务：安卓房主给双方各发 10 分，鸿蒙发起 5 分收款、安卓确认后，双方均显示安卓 5 分、鸿蒙 15 分；重新安装最新包后保留会话、余额和记录。安卓实际验证结束只读和新账本确认的取消分支。

界面证据为 `android-ui/`、`harmony-ui/` 下的 `local-*`、`cloud-grant-*`、`cloud-request-*`、`cloud-payment-*`、`cloud-restored-after-install`、`cloud-finish-confirm`、`cloud-next-confirm`。鸿蒙批量记录修复前后的行为通过本机流程重跑验证。测试用输入法首次设置和测试脚本定位失败与应用结果分开记录。

猎巫镇另用安卓、鸿蒙两个原生模拟器界面与两个 HTTP 测试参与者完成四人整局：实际创建/加入、准备、查看自己的身份、确认、夜间等待、房主开始秘密投票、投票及村民胜利。两端结算身份与公开日志一致，过程截图为 `hunt-*`，测试参与者结果为 `native-hunt-bots.log`。本代表局的两台模拟器均为村民；女巫、警长及特殊边界由前述 Java 和生产客户端测试覆盖，未把脚本参与者描述成额外真机。

## 发布与实际限制

更新后的服务器源码与部署说明打包在 `yigame-room-server.zip`，必须先部署新 JAR 才能让新版客户端使用新玩法。本轮仅启动本机测试服务，没有改动现有公网服务。

最终文件位于 `artifacts/cloud-expansion/release/`，包括两端 debug 安装包、独立 JAR、服务源码部署 ZIP、报告、SHA256 校验和和清单。可运行 `python scripts/package-game-verification.py --suite cloud-expansion` 重建交付目录；该脚本先检查构建/回归日志，再从明确文件列表打包，不包含运行时房间数据或凭据。

网络账本是房间当前局的数据，不是永久多账本档案。每局最多 2000 条成功指令，最多 30 个待确认收款；结束后保留只读记录，下一局清空前应导出。成员离开会锁定账本；待确认请求不会自动扣款。CSV 以长按复制提供。

全组合覆盖来自规则、Store 和真实 HTTP 测试；模拟器验证代表性界面流程，不能等同于所有实体设备、系统版本或真实公网弱网场景均已验证。上一轮全部游戏同机界面检查及修复见 `ONE_NIGHT_CLOUD_AND_OFFLINE_QA.md`。
