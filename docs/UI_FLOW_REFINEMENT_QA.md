# 界面与页面流程整理（2026-09-17 至 18）

## 范围与原则

本轮围绕首页入口、随机工具选择、游戏进入路径和公共视觉样式，配对调整 Android / KMP 与 Harmony 原生页面。KMP 的公共页面同时用于 Android 和 Web；Harmony 仍为配对维护的 ArkUI 页面。本轮没有迁移为统一 Compose 渲染，也没有修改服务器协议。

页面流程审查基于两端生产代码和导航实际连接关系。配置人数、选择角色、加入房间所需的昵称与房间信息属于有效输入；身份交接遮罩、秘密任务投票、不可逆操作确认属于必要环节。减少点击不以跳过这些环节为代价。

## 猎巫镇玩法边界

本轮重新查阅 [Facade Games 官方游戏介绍](https://www.facadegames.com/products/salem-1692) 和 [官方英文规则书](https://www.facadegames.com/files/rulebooks/salem-1692-rulebook-english.pdf)。发行方当前版本标注 2–12 人，其中 2–3 人使用额外变体；它并不是单人游戏。官方主持方案会区分参赛报幕者与不参赛主持人，并要求夜间信息隔离。

项目当前本地和云端猎巫镇是 4–12 人的单身份简化玩法，不包含原版多张审判牌、手牌与阴谋传染。原有本地页面允许同一个操作人记录女巫目标与警长守护，没有网络客户端的私有身份隔离。因此本地入口明确为额外主持人使用；所有人都希望参赛时建议各用设备进入网络房间。本轮保留规则引擎，不把文字和卡片优化描述成完整原版适配或无主持单人模式。

## 阿瓦隆现有同机变体

两端本地 `requiresTwoFailures` 的现有判断为：7 人第 4 轮需要两张失败票，8–10 人第 4、5 轮需要两张，其他轮次一张。云端 Java 的判断为 7 人以上仅第 4 轮需要两张。本轮对同机说明明确标注当前规则，并修正两次失败的旧文案，未改变任何投票或结算逻辑，也未声称本地与云端已统一为一套玩法。

同时移除 `TaskResultPhase` 内一个未被使用的旧“两次失败”布尔计算；生产胜负仍由原来的 `checkGameEnd` 决定。

## 视觉调整

公共卡片、按钮、对话框、顶部返回动作沿用首页的主题角色、较轻层次与圆角定义，避免新增页面各自硬编码风格。猎巫镇配置、发牌和阶段卡使用相同卡片层次；必要的阵营/错误语义色保留。

随机工具项收紧宽度，新增工具移到列表末尾；仅在对应方向确实还有内容时显示边缘渐隐提示。不得用始终存在的蒙层遮挡最后一个工具或“新增”。

### Harmony 实际界面操作

在 2584 × 1828 横屏模拟器上，已验证首页三项底栏与右上大厅、二级页返回、网络/局域网切换、局域网卡片顶部对齐；最终首页不再显示装饰性黑条。卧底配置后一次开始即到隐藏身份，猎巫配置不自动弹说明，狼人配置与你画我猜直达画板及更多菜单均正常。

随机工具已实际新增、修改、删除；竖向列表还有内容时底部渐隐，滚至末尾消失。发现并修复旧编辑层系统返回会退桌面的缺陷：改用原生弹窗承载原编辑器，新增和编辑时返回都只关闭弹窗；另以会话编号隔离异步保存与关闭回调，防止旧回调误关新窗口；未保存的改名不影响原配置，底栏恢复可用。所有临时工具已删除，原“跟随系统”主题已恢复。

分别检查了浅色与深色的首页、大厅、工具。详细证据与限制见 `artifacts/ui-refresh/harmony-ui/qa-summary.md`，该文件逐项列出截图与界面层级记录。

### 验证边界

Web 分发构建已通过，但本轮浏览器扩展无法连接，未执行 Web 页面交互验收。Android 公共 Compose 页面测试不能代替 Web 浏览器输入、滚动、返回和邀请链接的实测。
